# DSH installed-host run guide and evidence boundaries

Final tested composition: Windows DSH0.2.1-rc.3 / embedded Node24.21.0. See `run-2026-10-30T17-31-03.592Z-cce238ac` for exact outputs and final repaired source hashes (the earlier `run-2026-10-30T16-41-27.706Z-a740898f` success remains historical). No model, Agent or paid transport was used.

The test controller created five independent case directories under one newly allocated short native-temp root, each with fresh DSH_HOME, DSH_AGENTS_HOME, USERPROFILE, temp and empty cwd; telemetry disabled, credentials/proxies/acceptance switches omitted. Windows identity fields were explicitly fixture-local or neutral. The child checked exact environment keys/values and os.homedir before importing installed modules. Its network/subprocess/sensitive-file process tripwires remained empty.

For each case, repository stageRender→stageCommandAliases→installSkills prepared canonical/root/alias fixture skills and a real registry. A real Git fixture and external test policy were created. stageDshProfile generated both local plugin packages; existing generated directories were exposed through offline junctions in that profile's own node_modules. Package/patch/shim bytes were verified unchanged; no missing shim was supplied and no package manager ran.

The ASAR-aware installed Electron Node carrier loaded DSH's public `loadProfileDirectory('dsh', actualGeneratedDir, INSTALL_ANCHOR)` and `runProfile` with args:[], patchFiles:[] except the explicit missing-service negative overlay, and an explicit process-only empty launch-environment snapshot. This avoids CLI layered .env reads. Plugin IDs and exports were inspected before dispatch. The loader's own include fiber also appears in the actual roster alongside the four expected active IDs.

The clean case used real tools.register and ToolRuntime.execute for bounded fixture_write/read, then inspected systemPrompt.assemble(). Allowed operations executed actual fixture bodies and disk I/O; outside/.git/corrupt-policy rejections left body counters and protected bytes unchanged. Restoring policy bytes enabled the same loaded guard to execute again. Startup-negative cases captured real warnings/fiber failure or pending states and the acceptance controller refused every dispatch.

Failure results remain first-class evidence: attempt1 failed Git MAX_PATH before any host child; attempt2 failed Windows environment validation before installed imports. Neither is counted as a completed host control. Final success establishes only the generated-profile/index/fixture-tool pipeline. It does not establish native file tools, model consumption, slash-command execution, complete host fail-closed startup or OS sandboxing. In particular optional plugin apply failures return host exit0; the acceptance-level gate is not a production host enforcement guarantee.

The local controller and consumer were statically independently reviewed at SHA256 c8920b193dc965269169831e856c2f7258a718c95cab155e4524afc7050d2257 and c8b910fcee0e9e65a2615f297b0244e0d149a095b58e308bb1fe0ba38db3309e. Those local coordination scripts stay outside the publication. The shipped tested-source.json retains their hashes together with exact product/test hashes. To repeat these checks elsewhere, use the installed APIs/anchors in host-feasibility.md, the same isolated generated output, real ToolRuntime and ACTIVE checks; do not substitute a direct adapter callback or count exit0 as activation.
