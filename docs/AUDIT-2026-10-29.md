## 范围和方法

对本仓库 53 个运行时代码文件（`src/`、`bin/`、`scripts/`、`hosts-overlay/`）及全部测试、CLI 入口、CI、蓝图和功能矩阵做全库范围检查：枚举入口与危险操作，重点阅读权限/审批/状态、文件安装、模型请求、脱敏发布和身份缓存路径，再执行完整回归。不是对上游子模块全部代码的独立逐行审计，也不是无缺陷证明。

## 已修复问题

P1 表示应优先处理的数据安全/操作安全缺陷；P2 表示边界校验或资源控制缺陷。这里的优先级不是 CVSS 评分。

| 编号 | 级别 | 旧行为及影响 | 修复 |
|---|---|---|---|
| A01 | P1 | 导出的 `runModelReview()` 信任任意 gateway 对象，可绕过文件加载层的官方端点、明文网络、token 上限和字段类型校验 | 请求前重新编译验证配置；非法配置零请求；保留省略 schemaVersion 的旧内联调用简写；明确拒绝 Anthropic 官方端点 |
| A02 | P1 | 合法 HTTP 200 复核结果可在 findings/嵌套 usage 中回显当前 API key；网络/读体错误的动态代码字段也可泄露 key | 对返回字符串、usage 的 JSON 键和值以及动态错误诊断统一脱敏；不改变结构化 verdict 枚举 |
| A03 | P2 | `response.text()` 无大小限制，网关不遵守 max_tokens 时可耗尽内存；深嵌套 usage 还会造成递归溢出 | 流式读取最多 1 MiB，超限取消流；返回 JSON 的处理深度限制为 64 |
| A04 | P1 | `uninstall --purge` 只凭备份名称和 generator 标记删除目录，会删除升级后用户新加或编辑的内容 | 清理前按摘要和精确文件集合重新验证；新增文件、编辑、额外目录、链接或不可读内容均保留；预览与实际清理共用判断 |
| A05 | P1 | 安装只 lstat 辅助文件的叶节点，父目录 symlink/junction 可引入 staging 之外的内容；manifest 本身未要求普通独占文件 | 校验相对路径每一层；manifest、SKILL.md 和辅助文件必须为非链接、单链接的普通文件；拒绝发生在目标目录创建前 |
| A06 | P2 | v2 slug 缓存允许 `.`/`..`，可把项目状态归入 projects 之外 | 缓存采用与环境变量覆盖相同的路径段约束，非法缓存回退重新解析 |
| A07 | P2 | 私有仓库可见性缓存接受未来、字符串、null 或负时间戳，错误地把公开目标当私有目标 | 只接受非负、安全整数、且不晚于当前时间的检查时间；无效缓存重新查询 |
| A08 | P1 | 损坏的发布保护配置只有含字面量 `"sealed"` 才报错，转义键或不可读 ref 会被当作“没有策略” | 使用树枚举区分文件缺失和引用错误；已存在配置的所有 JSON 解析失败均拒绝，不输出配置内容 |
| A09 | P1 | 安装 pre-push hook 会覆盖已有 `pre-push.local`，损坏用户脚本 | 备份名已占用则在移动任一文件前拒绝；拒绝 hook 文件的链接/硬链接 |
| A10 | P1 | 生成的 shell hook 对安装路径只加双引号，路径中的 `$()` 可执行命令替换 | 用正确的 shell 单引号转义；实测包含 `$()` 和单引号的安装路径，既不产生注入文件又执行到正确二进制 |

另做一项防御加固：开发用 HTTPS 代理不再默认指向官方 DeepSeek 端点，必须显式提供 `DEV_GATEWAY_UPSTREAM` 和凭据；上游请求明确禁止自动跟随重定向。重定向用例在基线环境原本已通过，故不把它算作本轮新复现缺陷。

开发代理仍只适合专用测试子进程。其公开测试证书不是生产凭据，本轮没有更换它或扩大信任范围。现在需以 `DEV_GATEWAY_UPSTREAM=<明确授权的上游 URL>` 启动；健康探针不需要配置，但缺少配置的 POST 返回 503，不访问默认供应商。

## 保留的边界

- 文件预检查不是操作系统沙箱，检查和使用之间的竞态、同用户恶意进程以及不经过宿主标准执行链的插件仍不在本轮保证内。
- gateway 结构验证不证明用户已经授权；真实执行仍需可信控制器使用工作区外的配置、预算开关和独立凭据来源。自定义代理实际转发到哪里不能仅靠 URL 黑名单证明。
- 备份完整性依赖本地 manifest；本轮保护普通编辑/新增文件，不宣称能抵御拥有同等权限且同时伪造 manifest 的攻击者。
- 反复验证回归通过不等于两个宿主全功能对等。未验证的真实宿主交互、超时行为、设备/Docker/部署等项目仍沿用 FEATURE_MATRIX 的实际分级，不升级为 full。
- 原生宿主、付费模型质量、Mac 真机及用户云端电脑不是本轮测试环境。当前的阶段功能缺口不能用本次缺陷修复代替验收。
